## 宿題

基礎・実装・発展の3つすべてに取り組んだ。計測は 2026-10-26、Codespaces から実行。

### 基礎：同じ質問を3回ずつ、モデルと temperature を変えて実行

- 使ったモデル：gemini-3.5-flash-lite、gemini-3.8-flash
- やったこと：
  - `app/ask.py` に `--temperature` を追加（`generate_content` の `config` に `GenerateContentConfig(temperature=...)` を渡す。範囲外の値は実行前に弾く）
  - 「3レベル」の質問を、モデル2種×3回、flash-lite で temperature 0.0 / 1.0 / 2.0 ×3回 実行（`scripts/bench.py`）
- 結果：

  | 条件 | 出力トークン（3回） | 回答の傾向 |
  |---|---|---|
  | flash-lite / 既定 | 462, 742, 472 | 「スキルや理解度」「学習者の理解度や実装」など、毎回違う一般論 |
  | 3.8-flash / 既定 | 706, 772, 487 | 「達成度・難易度を3段階に分けた提出基準」と断定。表現は揺れるが方向は一貫 |
  | flash-lite / t=0.0 | 514, 527, 505 | 3回とも本文が異なる |
  | flash-lite / t=1.0 | 520, 565, 669 | 同上 |
  | flash-lite / t=2.0 | 571, 777, 670 | 同上。出力がやや長く、ばらつきも大きい |

- 気づき：
  - temperature を指定してもエラーにはならなかったが、t=0.0 でも3回の回答がすべて異なった。t=0 なら同じ回答になるという想定は、このモデル・この API では成り立たない。講義資料にあるとおり temperature は 2026-07 に非推奨になっており、指定が無視されているか、効きが弱い可能性がある（今回の結果だけでは区別できない）。
  - t=2.0 では出力トークンの平均とばらつきがやや大きいが、各条件3回だけなので差とは言い切れない。
  - どの条件でも内容は不正解のままで、揺れているのは表現と長さだけ。temperature は正しさを左右しない。

### 実装：会話履歴を保ったまま続けて質問する

- 使ったモデル：gemini-3.5-flash-lite
- やったこと：
  - `uv run python -m app.ask --chat` で対話モードにした。`client.chats.create()` の Chat オブジェクトが履歴を保持し、毎回履歴ごと送る
  - exit / quit / q / 空行 / Ctrl+D / Ctrl+C で終了。API エラー（429 など）が出ても落ちずに続けられる。失敗した質問は履歴に残らない
  - 1往復ごとにトークン数・応答時間・履歴の往復数を表示し、終了時に会話全体の合計を表示する
- 結果（`lectures/01/results/chat_demo.txt`）：

  | 往復 | 入力 | 内容 | 入力トークン | 出力トークン |
  |---|---|---|---|---|
  | 1 | 私の名前はMiraiです。一言で返事して | よろしく、Mirai！ | 14 | 5 |
  | 2 | 私の名前は何ですか？一言で | Miraiです。 | 29 | 4 |

- 気づき：
  - 2回目の入力 29 は、新しい質問だけでなく、1往復目の質問と回答（14＋5）も含んでいる。履歴を保つほど、毎回の入力トークンは累積で増える。長い会話では、要約や古い履歴の切り捨てが必要になる。
  - Chat の履歴は送信が成功したときだけ更新されるので、エラー時に履歴が壊れない。テスト（`tests/test_homework01.py`）で確認した。

### 発展：応答時間とトークン数を計測し、モデルと質問で比較

- 使ったモデル：gemini-3.5-flash-lite、gemini-3.8-flash
- やったこと：
  - `generate()` で応答時間（`time.perf_counter()`）とトークン数（入力・出力・思考）を毎回取得
  - `scripts/bench.py`：モデル×質問×3回などの計画を実行し、`results/runs.jsonl`（全回答を含む生データ）と `results/summary.md`（集計）を出力
  - 無料枠の上限に合わせて、モデルごとに呼び出し間隔を空ける（毎分の上限の 1.15 倍の間隔）。429 / 503 は指数バックオフで最大2回再試行し、試行回数も記録する
- 結果（各3回の平均、思考は3回の値）：

  | モデル | 質問 | 応答時間 | 入力 | 出力（3回） | 思考（3回） |
  |---|---|---|---|---|---|
  | flash-lite | LoRA | 6.4s | 7 | 774, 612, 577 | なし |
  | flash-lite | 3レベル | 5.1s | 21 | 462, 742, 472 | なし |
  | 3.8-flash | LoRA | 98.3s | 7 | 786, 793, 768 | 1004, 950, 958 |
  | 3.8-flash | 3レベル | 79.9s | 21 | 706, 772, 487 | 1207, 1077, 714 |

  21回すべて成功し、429・503 はなかった（再試行0回）。

- 気づき：
  - **3.8-flash は flash-lite の約15倍遅い**（1回30〜112秒、平均80〜98秒）。出力トークン数はほぼ同じなので、差は回答本文ではなく、本文より多い思考トークン（約1,000）と、無料枠での待ち時間の影響と考える（後者は推測。今回の計測では切り分けていない）。
  - **思考トークンは、表示される回答の外で消費される**。3.8-flash の課金対象の出力は、本文の約2.2〜2.5倍になる。それでも「3レベル」は不正解で、知らないことは考えても分からない。
  - **レート制限との関係**：3.8-flash は1回90秒前後かかるため、順番に呼ぶ限り毎分5回の上限には届かない。効いてくるのは1日10〜20回の上限で、今回の6回でもその3〜6割を使った。逆に flash-lite は1回3〜8秒なので、間隔を空けずに連続で呼ぶと毎分10〜20回になり、毎分15回の上限に当たりうる。モデルによって、効いてくる制限が毎分か1日かで変わる。
  - 試行錯誤や繰り返し比較は flash-lite で行い、3.8-flash は数問の確認に絞るのが無料枠では合理的（講義資料の推奨とも一致）。

### 残した課題

- API 呼び出しにタイムアウトを設定していない。3.8-flash で110秒かかったので、実運用ではタイムアウトと、超えたときの扱いが必要。
- 連続で呼んで 429 を発生させる実験（`python -m scripts.bench --burst 20`）は、無料枠を節約するため実行していない。
- 各条件3回では統計的な差は言えない。temperature の効きを確かめるには、回数を増やし、回答の一致率を測る必要がある。
